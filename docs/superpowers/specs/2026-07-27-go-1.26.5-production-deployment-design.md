# Go 1.26.5 Production Deployment Design

## Goal

Upgrade the service from Go 1.24.5 to Go 1.26.5 and redeploy the existing
Vercel project to production without changing application behavior.

## Scope

- Change the root `go.mod` directive from `go 1.24.5` to `go 1.26.5`.
- Update active repository guidance in `AGENTS.md` and `CLAUDE.md` from Go
  1.24.x to Go 1.26.5.
- Leave historical specifications and implementation plans unchanged.
- Do not add a `toolchain` directive or a custom Vercel runtime configuration.
- Do not change application source code or dependencies unless Go 1.26.5
  verification exposes a concrete compatibility issue.

## Deployment Approach

Vercel detects the Go version from the root `go.mod`, so changing the module
directive is sufficient to select Go 1.26.5 for the serverless functions.

Use the Vercel CLI to:

1. Confirm an authenticated Vercel account.
2. Identify and link the existing Vercel project associated with this
   repository.
3. Stop for user direction instead of creating a new project if the existing
   project cannot be identified unambiguously.
4. Deploy the verified working tree to production.
5. Inspect the deployment and retain its production URL.

Direct CLI deployment is preferred over pushing `main` because it publishes
the verified source without introducing an unrelated remote Git mutation.

## Verification

Before deployment, use the installed Go 1.26.5 toolchain to run:

```bash
GOCACHE=$(pwd)/.cache/go-build go test ./...
GOCACHE=$(pwd)/.cache/go-build go build ./...
GOCACHE=$(pwd)/.cache/go-build go vet ./...
```

Confirm that `go mod tidy` would not change `go.mod` or `go.sum`.

After deployment:

- Confirm Vercel reports a successful production deployment.
- Request the production `/api/ping` endpoint and require an HTTP success
  response with the expected health body.
- If the project exposes deployment metadata, confirm the deployment was
  built from the source containing `go 1.26.5`.

## Failure Handling

- If Go verification fails, do not deploy; diagnose and resolve only
  compatibility issues caused by the version upgrade.
- If Vercel authentication is missing, request the user's login authorization.
- If more than one Vercel project is plausible, ask the user to select the
  target rather than creating or deploying to a new project.
- If deployment succeeds but the health check fails, preserve the deployment
  URL and report the observed status and response without claiming success.

## Success Criteria

- Active project metadata declares Go 1.26.5.
- The complete test, build, and vet commands pass under Go 1.26.5.
- The existing Vercel project has a successful production deployment.
- Its production `/api/ping` endpoint responds successfully.
